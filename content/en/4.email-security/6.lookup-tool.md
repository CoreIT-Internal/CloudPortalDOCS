# Lookup tool

The lookup tool is a troubleshooting tool for DNS and email security. You can look up individual DNS records or run a combined quick check of a domain. The tool reads what is published in public DNS — it changes nothing.

You'll find it under **Email security** → **Lookup**. The page is called **DNS lookups and email security check** and has two tabs: **DNS lookup** and **Mail Security Quick Check**.

From a zone in **DNS** or **Cloudflare DNS** you can also click **Check email security**. This opens **Mail Security Quick Check** with the zone's domain, and the check runs right away.

The tool requires **View email security policies**.

## DNS lookup

Use this tab to see the raw DNS records for a domain or hostname.

1. Enter **Domain or hostname** (for example `customer.com`).
2. Choose which **Record types** to look up by clicking the tags: MX, TXT, CNAME, A, AAAA, NS and SOA. Your choice is saved in the browser for next time.
3. Click **Look up**.

The result is shown per type. MX and SOA have their own columns, for example priority and MX host, or serial and TTL values. You can copy individual values and run the lookup again with **Re-run**.

::tip
If there is no record of a selected type, it says "No … records found." If it also says that the lookup took too long, or that the DNS server did not answer, the record was not checked — it may exist.
::

## Mail Security Quick Check

This tab runs a combined check of the domain's email security and shows an overall status: **OK**, **Warning** or **Error**.

1. Enter **Domain**.
2. If needed, enter **DKIM selectors (optional)**. The selectors are in signed messages (`s=` in `DKIM-Signature`). Enter at most five, separated by commas or spaces. Common selectors are checked anyway.
3. Click **Run check**.

Each check gets a status of its own: **OK**, **Warning**, **Error**, **Unknown** or **Skipped**. Warnings and errors explain what should be fixed.

| Check | What is checked |
| --- | --- |
| **MX** | Which mail servers receive email, including implicit MX (only A/AAAA) and null MX. |
| **SPF** | A static analysis of the SPF record (see below). |
| **DMARC** | The record at `_dmarc.<domain>`, the policy that governs the domain and the report addresses. |
| **DKIM** | The keys for the selectors you entered and a few common selectors. |
| **MTA-STS** | The `_mta-sts` TXT record, the policy file, the mode, **max_age** and whether the policy covers the domain's MX. |
| **TLS-RPT** | The report addresses at `_smtp._tls.<domain>`. |
| **MTA-STS policy host (HTTPS)** | That the policy file can be fetched over HTTPS. |
| **DNSSEC** | Whether the domain is signed and whether validation holds. |
| **CAA** | Which certificate authorities may issue certificates for the domain. |
| **BIMI** | The BIMI record at `default._bimi.<domain>` and its URLs for logo and certificate. |

### About the checks

- **SPF:** "A static analysis of the record. It is not evaluated for any sender address." The number of terms that query DNS counts the record's own terms. Included records add their own, so the number is a floor: over 10 here is always over the limit. `include` and `redirect` targets are looked up, and a target without an SPF record is an error. A record ending in `+all` is an error, and `?all` gives a warning.
- **DMARC:** if the domain has no record of its own, the record on the organizational domain applies, with `sp=` for subdomains. A report address in another domain must be authorized by that domain, otherwise no reports are sent there. An address that is not `mailto:` gives a warning.
- **DKIM:** DNS cannot list selectors, so the list is not exhaustive. If no key is found, that does not mean the domain has no DKIM: enter the selector from a signed message. An RSA key shorter than 1024 bits is an error, and one of 1024 bits gives a warning.
- **MTA-STS:** under **MX without a pattern** are the domain's MX that no pattern in the policy covers. In enforce, no mail is delivered to them.
- **MTA-STS policy host:** "This check confirms that HTTPS answers with a certificate valid for the name. It does not show the certificate issuer or expiry."
- **DNSSEC:** the state is read from the answers of two validating resolvers (Cloudflare and Google) over DNS over HTTPS. The portal does not validate itself. The state is **validated**, **not signed**, **failing** or **unknown**.
- **CAA:** the check warns if CAA blocks the certificate that the portal's hosting of the MTA-STS policy needs.

### Unknown is not missing

If DNS did not answer, or a check did not finish within its time limit, it is shown as **Unknown** — never as the record missing. Run the check again a little later.

::note
If a domain publishes a null MX record (it explicitly does not accept email), the mail-related checks are skipped. DNSSEC and CAA are still relevant for the domain itself.
::

### Limits

- The tool only looks up public domains: "Enter a public domain. IP addresses and internal names are not looked up."
- If you make many lookups in a short time it says "Too many lookups in a short time. Wait a minute and try again."

## Jump to DNS lookup

Click **Look up in DNS** on a card in Mail Security Quick Check. This opens **DNS lookup** with the right name and record type filled in, so you can inspect the underlying record.
