# RewriteMaps

A RewriteMap is a group of redirects in a zone that are published together. It fits when many rules belong together, for example when a website moves. The rules in a map apply only once the map is published.

The map's rules are ordinary redirects. They are created and edited in the same way as a [custom rule](/en/domains-and-dns/redirects#create-a-custom-rule).

## Open RewriteMaps

1. Open the zone under **Domains** → **DNS** → **Redirects**.
2. Click **RewriteMaps** in the zone header.

The list shows the zone's maps with the columns:

- **Name**
- **Status** — **Draft**, **Published** or **Archived**, and what the map needs next. See The map now below.
- **On the edge** — how many of the map's rules the edge serves, for example "98 / 100".
- **Verification** — the outcome of the latest verification.
- **Observed requests 30 d** — a lower bound, since answers from the browser's cache never reach the edge.

Archived maps are shown when you select **Show archived**. Click **View** to open the map's rules. Other actions are in the row's menu. A greyed-out menu entry says why the action is not possible.

## Create a RewriteMap

1. Click **Create RewriteMap**.
2. Give the map a **Name** and optionally a **Description (optional)**.
3. Click **Create draft**. The empty map opens.

You can also create a map straight from a file. See [Import redirects](/en/domains-and-dns/import-redirects).

## Add rules

When the map is open, a box at the top shows the map's name, its status and how many rules are in traffic. It offers three ways to add rules:

- **Add rule** — opens the same form as for a custom rule.
- **Add a new row** — a quick row with host, path, destination, type and status code. "Press Enter to save. Host, type and status code persist across rows."
- **Paste multiple rows** — paste from Excel, CSV or text, one row per rule. The columns are host (optional), source path, destination, type and status code. The panel shows which rows are valid before you click **Add … rules**.

The map's rules are listed below the box, and you can edit, switch off and delete them like other redirects.

## Publish a map

1. Choose **Publish** in the map's menu, or click **Publish →** in the status column.
2. The **Publish map** panel shows what will happen before anything changes:
   - How many rules the map has and how many are switched on.
   - Obstacles under "The map cannot be published as it stands:", for example that the map has no rules, has duplicates, has rules that take the same requests at the same priority, or would not fit on the edge. They have to be fixed first.
   - **Rules switched off when the map is published** — other active rules that take the same addresses. The button is then called **Override and take over (…)**, and the conflicting rules are switched off but not deleted.
   - **Overlaps** — rules on the same host that take some of the same requests at different priorities. That is allowed: the higher priority answers.
   - **Hosts** — the map's hosts, **On the edge** or **New**, and how many DNS records are created.
   - **Quota and room** — the certificate quota for new hosts and how much of the organization's room on the edge is used.
3. Click **Publish**.

If anything changed since the preview, nothing is published. The panel then shows a new preview to review.

::note
DNS, quota and room are estimates that are checked again when the publish runs. New hosts get a certificate when they are activated on the edge. If the certificate quota does not allow it, some hosts wait, but the publish is not refused. If DNS records that someone else created have to be removed, that happens only after approval, see [Approve DNS](/en/domains-and-dns/redirects) under Redirects.
::

## The map now

For a published map the status column shows the next step, with a link to what needs doing:

- "Publishing: the edge has not confirmed it yet."
- "Waiting for DNS · hosts: …" — **Show the hosts**. The hosts are activated when their DNS points at the edge.
- "Active · failed checks: …" — **Show the failures**.
- "Active · rules not published: …" — **Show the rules**.
- "Active"

Choose **Details** in the menu for the **The map now** panel. It shows how many rules are on the edge, hosts waiting, failed checks and rules not published. It also lists rules that have had no observed requests in 90 days, to help when you clean up.

### Verify

Choose **Verify** for a published map. The edge is then probed rule by rule, and the result fills in under **Verification** as it comes in: passed, wrong answers, technical obstacles, rules without a test address and rules not tested yet.

A regular expression has no address it is certain to match, so it is not probed. Try an address of your own with **Test an address** in the map's menu. There the draft is tested as if the map were published.

## Matching options

Choose **Matching options** in the menu. They hold for every rule in the map and are off by default:

- **Case does not matter** — `/About` matches `/about`, `/ABOUT` and `/aBout`. Applies to the letters a–z. Characters such as å, ä and ö match exactly as written.
- **With or without a trailing slash** — `/about` matches `/about/`, and `/products/*` matches `/products`.

Regular expressions are not affected. For a published map the change is checked as a publish is and reaches the edge at once. A version is saved first, so the change can be undone.

## Change the rules with a file

1. Choose **Re-import rules** in the menu and choose a file. The file format is described under [Import redirects](/en/domains-and-dns/import-redirects#the-file-format-cloudportal-v1).
2. Choose what should happen to rules the file does not mention:
   - **Replace the map's contents** — they are removed.
   - **Add and update** — they are kept.
3. Review the summary and the **Updated**, **Added** and **Removed** tabs.
4. Click **Apply**.

It is best to start from an export of the map. It has rule ids, so each rule is updated in place. Without rule ids the rules are matched on host and path, and a changed path becomes a new rule.

- If the file has rows that cannot be read, no part of it is used. Fix the file, or fetch the rows with **Download the rows with errors** and fix them there.
- If more than half of the map's rules are removed, you type the map's name to confirm.
- A published map stays published. If the change would cause duplicates or conflicts, it is stopped.

## Versions

Choose **Versions** in the menu. "The map's rules are saved before a reimport or restore changes them. The ten newest versions are kept." A version is also saved before the matching options change.

Click **Restore** to replace the map with a version. Rules added since then are removed.

## Unpublish, archive and delete

- **Unpublish** — the map's rules stop applying and the map becomes a draft again.
- **Archive** — the map stops applying at once and can no longer be changed or published.
- **Delete** — deletes the map and all its rules permanently. A published map has to be unpublished or archived first.

The permissions for maps are described under [Redirects](/en/domains-and-dns/redirects).
