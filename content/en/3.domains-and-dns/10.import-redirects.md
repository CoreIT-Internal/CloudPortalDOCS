# Import redirects

If you have many redirects, the easiest way is to collect them in a file. You can import the file into one zone, or for the whole organization at once. An export has the same format, so you can export, edit in a spreadsheet and import again.

## Import into a zone

1. Open the zone under **Domains** → **DNS** → **Redirects** and click **Import**.
2. Choose how the rules are imported:
   - **Individual redirects** — the rules are added straight to the zone.
   - **As RewriteMap (draft)** — the rules are collected in a new [RewriteMap](/en/domains-and-dns/rewritemaps) that you publish when you are ready. Suits large moves.
3. Click or drag a `.csv` or `.txt` file to the box.
4. Review the preview. Rows with errors are shown first, with the reason, followed by the rows that will be imported. The **Code** column says **Ready**, **Ready (off)** or **Error**.
5. Click **Import**. The button shows how many rows will be imported.

Rows with errors are not imported. Select **Show only rows with errors**, and click **Download the rows with errors (…)** to get a file with just those rows, their line numbers and the error. Fix the file and import it again.

For ready-made examples, click **Download Sample File** or **Download RewriteMap example**.

### As individual redirects

**Skip existing redirects with same source path** is selected by default. Rows that already exist as an active rule with the same destination are then skipped. A row that takes the same addresses as an active rule but has another destination is never imported. Change or delete the existing rule first.

As individual redirects, at most 1,000 rows are taken at a time. Import larger files as a RewriteMap. If you have not chosen a way and the file has many rows, the portal suggests a RewriteMap: "Large file detected (… rules)".

### As a RewriteMap

1. Give the map a **Name**. It is prefilled with the file's name.
2. Optionally type a **Description (optional)** and choose the **Matching options**, see [RewriteMaps](/en/domains-and-dns/rewritemaps).
3. Click **Import as RewriteMap (draft)**. The RewriteMaps page opens with the new map.

Under **Show advanced options** there is **Publish immediately**: "Rules become live in traffic immediately after import. Only use for pre-reviewed files."

::note
In a RewriteMap every rule starts switched on, even rows that are off in the file. The map's publication decides when they apply. Duplicates in the file do not stop the import, but the map cannot be published until they are removed.
::

## The file format (CloudPortal v1)

The file is a CSV file, preferably with a header row, or a plain text file. An export from the portal always follows the format.

### Columns

| Column | Content |
|---|---|
| `host` | The host, for example `www` or `www.example.com`. Empty means the zone itself. Optional. |
| `sourcePath` | The source path, for example `/old-page`. Required. |
| `destinationUrl` | The whole destination address. Required. |
| `redirectType` | `simple`, `wildcard` or `regex`. Empty means `simple`. |
| `statusCode` | `301`, `302`, `307` or `308`. Empty means `301`. |
| `isActive` | `true` or `false`. Also `1`/`0`, `yes`/`no`, `ja`/`nej` and `SANT`/`FALSKT`. Empty means switched on. |
| `ruleId` | The rule's id, which an export writes. On a re-import into the same RewriteMap, that exact rule is updated. |

- The headers can come in any order. Other columns are ignored, and the portal says which: "Columns that are ignored: …".
- On a re-import into a RewriteMap, an empty cell means the rule keeps its own value.
- Columns are separated by comma, semicolon or tab. A value that contains the separator is written in quotes.
- Without a header row the columns are read in the order `sourcePath`, `destinationUrl`, `redirectType`, `statusCode`, `isActive`, and the host is the zone itself.
- A text file has one rule per line, separated by spaces: source path, destination, type and status code. For example `/old-page https://example.com/new-page simple 301`.
- Empty lines and lines starting with `#` are skipped.
- Every row is checked with the same rules as the custom rule form. In the destination, write `${1}` for what `*` or a group matched.

### The format line

An export starts with a format line, for example `#cloudportal-redirects v1 options=ci+ts`. `options` are the map's matching options: `ci` for case and `ts` for trailing slash. If you import the file as a new RewriteMap, the options are preselected. A file of your own needs no format line.

A file from a newer version of CloudPortal cannot be read: "The file was written by a newer version of CloudPortal and cannot be read here."

### Example

```csv
#cloudportal-redirects v1
host,sourcePath,destinationUrl,redirectType,statusCode,isActive
,/old-page,https://example.com/new-page,simple,301,true
www,/products/*,https://example.com/shop/${1},wildcard,301,true
,^/blog/(.+)$,https://example.com/articles/${1},regex,302,false
```

### Files from Excel

- Save as "CSV" or "CSV UTF-8". Both work. If the file is not UTF-8, the portal says how it was read: "The file was read as … (what Excel saves as "CSV"). Accented letters come through."
- `SANT` and `FALSKT` (Swedish Excel's TRUE and FALSE) are read as on and off.
- If you opened the file with **From Text/CSV**, Excel sometimes adds the headers `Column1`, `Column2` and so on. That row is ignored, as are empty rows.
- An export is marked as UTF-8, so that Excel shows accented letters correctly.

## Import for several zones

With one file for the whole organization, a draft map is created per zone. Nothing is published in the import.

1. Go to **Domains** → **DNS** → **Redirects** and click **Import for several zones**.
2. Click **Choose a file**. "CSV or text, at most 5 MB and 20,000 rows."
3. Review the preview:
   - a summary with the number of rows, zones, rows without a zone and invalid rows
   - **Matching in the maps**, which applies to all new maps
   - an estimate of whether everything fits on the edge
   - **Zones**, with the number of rules and the **Map name** for each zone
   - **Rows without a zone** and **Invalid rows**, with the reason for each row
4. Click **Import … zones as drafts**.
5. The result shows which zones got a map. Click **Open the map** to review it.

Every row needs the host's full name, for example `www.example.com`. A host goes to the most specific zone you reach. A zone shared with you, or that is hidden or blocked, does not take the row, and the row is never moved to a parent zone.

If a zone failed, choose the same file again and click **Retry the zones that did not finish**. Zones that are already done are not created a second time.

### Publish all

After the import you can click **Publish all (…)**. Maps that need no review are published one at a time. A map with duplicates, conflicts, ambiguous rules or that does not fit stays a draft and is marked "Review: …". The page updates by itself, and you can leave it.

## Export

1. Click **Export** in the zone header.
2. Choose **CSV (comma separated)** or **Text (one per line)**.
3. Click **Export All**. If the list is filtered, you can choose **Export Filtered** instead for what is shown.

**Export All** includes all the zone's rules, including those in RewriteMaps. The CSV file has the format line and the columns `host`, `sourcePath`, `destinationUrl`, `redirectType`, `statusCode`, `isActive`, `hits30d`, `rewriteMap`, `createdAt` and `ruleId`. On import, the columns described above are read and the rest are ignored.

You export a single RewriteMap with **Export (CSV)** in the map's menu. The file gets the map's name and its matching options.

::tip
Choose CSV if you want to import the file again. The text format is for reading and comparing.
::

## Permissions

- **Import redirects** is required to import.
- Importing as a RewriteMap, or for several zones, also requires **Create redirects**.
- **Publish all** requires **Edit redirects**.
- **Export redirects** is required to export.
