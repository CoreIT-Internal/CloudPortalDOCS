# App Hosting

With App Hosting you bring home an app you built in Lovable, Cursor, Claude Code, Bolt or any Git repository. You import the app from its repository, and CoreIT puts it into service for you. You keep building in your tool as usual.

In the portal the module is called **App Platform**. You find it under **Applications**. The menu has two items: **Overview** and **Import**.

## The start page

The start page has four parts:

- **Bring your app home** — the cards **Bring your Lovable app home** and **Bring an app home from Git**. Both open the import wizard. The cards are only shown if you have the **Import and create applications** permission.
- **My apps** — your organization's apps. Select an app to open its page.
- **Available hosting environments** — "Environments you can actually deploy to in your current view." Each row shows the kind of environment: **CoreIT Hosting**, **Azure (CoreIT-managed)** or **Azure (your subscription)**.
- **Three ways to run your app** — a collapsed section that briefly describes different ways to run an app. It is information only. You do not choose anything there.

If it says "No hosting environment activated yet", your organization has no hosting environment yet. You can still import an app. CoreIT then prepares a hosting location for it.

Apps can also be found in the portal's global search, as the type **Application**.

## Where the app runs

CoreIT decides where the app runs, based on your agreement. You see it on the app's page under **Hosting location**. There are two cases:

- **CoreIT Hosting** — the app runs in CoreIT's own datacenter. CoreIT builds the app and puts it into service. The app gets its own address, for example `myapp.coreitsite.app`, and the app's page shows its status and address.
- **Other hosting environments** — the import prepares the hosting environment and a deployment plan. The app does not run until CoreIT has put it into service for you. The app's page says so right below the status.

## What you can do

- **Import an app** from a Git repository. See [Import app](/en/app-hosting/import-app).
- **Connect GitHub**, so you can pick the repository from a list. See [Connect GitHub](/en/app-hosting/connect-github).
- **Add environment variables** when you import. See [Secrets and environments](/en/app-hosting/secrets-and-environments).
- **See the status and address** of the app. See [Your app](/en/app-hosting/deploy-app).
- **Choose a size** for the app. See [Your app](/en/app-hosting/deploy-app).
- **Add a custom domain**. See [Domains and publishing](/en/app-hosting/domains-and-publishing).
- **Delete an app**. See [Your app](/en/app-hosting/deploy-app).

## Permissions

| What you want to do | Permission | Included by default for |
| --- | --- | --- |
| Import an app | **Import and create applications** | Owner, Admin, Operator, Member |
| Connect GitHub or a private repository | **Manage providers and source connections** | Owner, Admin |
| Add environment variables | **Manage environment variables and secrets** | Owner, Admin, Operator |
| Change size, domains and health checks | **Change application settings** | Owner, Admin, Operator, Member |
| Use **Deploy new version** | **Prepare deployments** | Owner, Admin, Operator, Member |
| Delete an app | **Delete applications** | Owner, Admin |

**Manage providers and source connections** and **Manage environment variables and secrets** are sensitive permissions. Read more under [Roles and permissions](/en/organization/roles-and-permissions).
