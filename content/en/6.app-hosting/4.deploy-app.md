# Your app

Open the app under **My apps** on the start page, or search for it in the portal's global search. The app's page answers the most important questions first: is the app running, where is it, and do you need to do anything.

## Choose an environment

If the app has several environments, the **Environment** selector is shown at the top, for example with `production` and `staging`. Everything on the page applies to the environment you have chosen.

## Status and address

The status card at the top shows the app's state with a coloured dot and a short sentence:

| Status | What it means |
| --- | --- |
| **Running normally** | The app is in service and responding. |
| **We are working on your app** | Something is in progress right now. You do not need to do anything. |
| **We are preparing hosting** | The deployment plan is ready and CoreIT is preparing hosting. |
| **Not deployed yet** | The app has not been put into service. |
| **Something went wrong during deployment** | The latest deployment failed. |
| **The app is not responding** | The app did not respond at the latest check. |
| **We need to check something with you** | CoreIT needs to check something with you. |
| **Your app needs a few values from you** | The app is missing environment variables. |
| **Waiting for the domain to point here** | The domain's DNS does not point correctly yet. |
| **Waiting for you** | CoreIT is waiting for information from you. |
| **Status not verified** | The app is in service, but it has not been checked recently. |
| **We can't tell the status right now** | The portal cannot tell how the app is doing right now. |

Below the status, the app's address is shown as a link. If there is an address that does not respond yet, it says "The address is being prepared". A custom domain that is ready is shown instead of the platform's address. Read more in [Domains and publishing](/en/app-hosting/domains-and-publishing).

### On CoreIT Hosting

CoreIT builds the app. Every build becomes a version, which you publish in the **Versions** panel right below the status card. The app gets an address on `coreitsite.app`, for example `myapp.coreitsite.app`. The status card shows the address and the app's status.

### In other hosting environments

Right below the status it says "The app is not running yet. This prepares the hosting environment and the deployment plan — CoreIT puts the app into service for you."

The **Deploy new version** button creates a new deployment plan, for example when you have changed the app. CoreIT does the actual deployment. The button requires the **Prepare deployments** permission.

Next to the button, another button may be shown when the status needs something from you: **Fill in values**, **Manage domain** or **Contact us**. Environment variables and domains are described in [Secrets and environments](/en/app-hosting/secrets-and-environments) and [Domains and publishing](/en/app-hosting/domains-and-publishing). If you need help, [contact support](/en/support/contact-support).

## Versions

On CoreIT Hosting, the app's page shows the **Versions** panel, right below the status card. There you see whether the app answers and which version is live. There you also publish a new version, approve a switch or roll back to an earlier version.

The panel applies to the environment you have chosen under **Environment**. Read more in [Versions and publishing](/en/app-hosting/versions-and-publishing).

## Facts about the app

The page shows four facts about the app:

- **Code** — the repository, as a link, and the branch in use.
- **Hosting location** — where the app runs, for example **CoreIT Hosting**. CoreIT chooses and manages the hosting location.
- **Size** — for example "0.5 CPU · 1 GB RAM · 10 GB storage", sometimes with the size's name. Below the value it says "Recommended for this app" or "Chosen by you". If the size is not decided yet, it says "Size is chosen when the hosting location is prepared".
- **Environment variables** — for example "3 configured", and "1 missing" if the app needs more values.

If values are missing, the box "Your app needs these values" is also shown, with one line per value, for example "Your app needs `DATABASE_URL` before it can be put into service."

If the code is on GitHub and the connection lacks permissions, a warning is shown with the **Manage GitHub connection** link. See [Connect GitHub](/en/app-hosting/connect-github).

When the repository has changed since the last analysis, "A new version is available in GitHub" is shown. Select **Analyze again** to read in the latest code. This requires the **Analyze repositories** permission.

## Change size

1. Select **Change size** under **Size**.
2. Under **Choose a size**, choose:
   - **Automatic size** — "We recommend and adjust the size to fit your app."
   - a named size. The size that fits the app is marked **Recommended**. If the size has a price, it is shown per month.
3. Select **Save size**. **Cancel** closes without changing anything.

CPU can be a fraction of a core, for example 0.5 CPU. If you choose **Automatic size** again, the platform takes over the choice. You need the **Change application settings** permission.

## Your app

Under the **Your app** heading you find:

- **Domains** — the app's custom domains. See [Domains and publishing](/en/app-hosting/domains-and-publishing).
- **Database** — a link to the app's database. The import does not move your database; it stays where it is.

## Advanced

The **Advanced** section stays closed until you open it. Changes here require the **Change application settings** permission.

- **Deploy branch** — "The branch that gets deployed. The workflow triggers on pushes to it." For repositories on GitHub you pick the branch from a list; otherwise you type its name. Save with **Save branch**. When you change the branch, the analysis is re-run on the new branch.
- **Build configuration** — framework, runtime, build command and package manager. Save with **Save**, or select **Reset to detected** to go back to what the portal found. Changed values are marked **Overridden**.
- **CI/CD — delivery method** — choose how the app reaches the environment: **Manual deploy from the portal**, **GitHub Actions per release** (marked **Recommended**) or **GitHub Actions + manual deploy**. See also below.
- **Health checks** — monitor that an address responds. See [Domains and publishing](/en/app-hosting/domains-and-publishing#health-checks).
- **Plan / preview** — "What will be created — before anything is applied." Shows, among other things, the delivery method, the environments and which secrets are used (names only, never values).

### The workflow file

Under **CI/CD — delivery method** you see the workflow file that belongs to the delivery method.

1. Review the file.
2. Select **Download workflow.yml** if you want to add it yourself, or **Commit to repo** to add it directly.
3. Confirm "Commit the workflow to the repo?" with **Yes, commit**.

**Commit to repo** is only available for repositories on GitHub where the connection has write access. For other repositories, download the file and add it yourself.

::tip
To change the file, select **Customize workflow**, edit it and select **Save customization**. A customized file is marked **Custom**. With **Reset to generated** you go back to the portal's version.
::

## Delete the app

At the bottom is the **Danger zone**. It is only shown if you have the **Delete applications** permission, which Owner and Admin have by default.

1. Open **Danger zone**.
2. Read the lists **This will be removed** and **This is NOT touched**. The app's environments, deployment plans, stored environment variables and domains are removed. Your Git repository and its code are not touched.
3. Type the app identifier shown above the field.
4. Tick "I understand this permanently deletes the app and cannot be undone."
5. Select **Delete application**.

::warning
Deletion cannot be undone.
::
