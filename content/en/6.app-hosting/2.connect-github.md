# Connect GitHub

Once a GitHub account is connected, you pick the repository from a list when you import an app. The connection is made with the **CoreIT CloudPortal GitHub App**, which you install on the repositories you choose.

::note
The app only sees the repositories you give it access to on GitHub.
::

## Who can connect GitHub

You need the **Manage providers and source connections** permission. It is a sensitive permission that Owner and Admin have by default. The same permission is needed to disconnect an account.

Without the permission you can still import a public repository, or choose a connection an administrator has already made. See [Import app](/en/app-hosting/import-app).

## Find the Connect GitHub page

The **Connect GitHub** page has no menu item of its own. You reach it from the import wizard:

- **Connect GitHub →** is shown when no GitHub account is connected yet.
- **Manage the GitHub connection →** is shown below the repository list when an account is already connected.

## Connect a GitHub account

You connect the account yourself. The connection is completed automatically when you return from GitHub.

1. Select **Install GitHub App** on the **Connect GitHub** page. "You'll be taken to GitHub to choose which repos the app can access, then brought back here automatically."
2. Sign in to GitHub if you are not already signed in.
3. Choose the account or organization, and whether the app should see all repositories or only the ones you select.
4. Confirm the installation. You return to the portal, where "Finishing the connection …" is shown for a moment.
5. Then **GitHub connected** is shown. The account is now connected to your organization.

Select **Continue — import app →** to go on to the import wizard. The account you just connected is then preselected.

### Connect more accounts

With **＋ Connect more GitHub accounts ↗** you install the app on another GitHub account or organization. GitHub opens in a new tab. When you are done, you come back to the **Connect GitHub** page, and the account is connected in the same way.

::note
An installation of the GitHub App can only be connected to one organization in the portal. If it is already connected to another organization, the portal shows "We cannot find a GitHub installation for this organisation."
::

## GitHub connected

When the connection is complete, **GitHub connected** is shown with:

- **Account** — the GitHub account or organization.
- **Type** — whether it is a user account or an organization.
- **Status** — for example **Installed**.
- **Connected repos** — how many repositories the app can access, and a list of them.

From here you can:

- select **Continue — import app →** to go straight to the import wizard,
- select **Back to overview**,
- open **Manage the installation on GitHub ↗** to change which repositories the app sees,
- select **＋ Select more repos in GitHub ↗** or **＋ Connect more GitHub accounts ↗**.

## Connected GitHub accounts

On the **Connect GitHub** page, **Connected GitHub accounts** lists the accounts where the app is already installed for your organization. Each row shows the account name and a status label:

- **Installed** — the connection works.
- **Missing permissions** — the app is installed but needs more permissions (see below).
- **Suspended** — the installation is suspended on GitHub.
- **Repo removed** / **Uninstalled** — the connection needs to be restored.

To give the app access to more repositories, select **Manage the installation on GitHub ↗** on the account's row. Then select **⟳ Refresh** in the import wizard so the new repositories appear.

## Missing permissions

To build the app from GitHub, the GitHub App normally needs to be able to:

- write content in the repository (to add a workflow file),
- write files under `.github/workflows`,
- read and write the repository's Actions secrets.

If something is missing, a warning is shown on the app's page: "The GitHub connection lacks permission to write the workflow and Actions secrets. Reinstall the GitHub App with the right permissions and try again." The warning lists what is missing. The **Manage GitHub connection** link opens GitHub, where you give the app the right permissions.

::warning
If permissions are missing, the build cannot be completed. Fix the permissions on GitHub before you continue.
::

## Disconnect an account

1. Select **Disconnect** on the account's row.
2. The portal asks: "Uninstall the app from this GitHub account? It will be removed on GitHub."
3. Select **Yes, disconnect**, or **Cancel**.

::warning
An account used by one or more apps cannot be disconnected. The portal then answers, for example, "Can't disconnect — in use by 2 app(s). Remove the apps first." First delete the apps that use the account, then disconnect it.
::
