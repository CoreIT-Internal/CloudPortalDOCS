This page describes how App Platform builds and runs an app, and what the repository must meet for that to work. It is written so that an AI agent can read it and compare it with a repository. As a person, you can give the agent the link, and it does the comparison for you.

**Contract revision 2 (2026-11-26).** The revision is raised when something on the page changes that affects what a repository must meet. Revision 2 adds Python apps.

The page is also available as plain Markdown, which is easier for an agent to read:

- English: `https://docs.coreit.cloud/raw/en/app-hosting/for-ai-agents.md`
- Swedish: `https://docs.coreit.cloud/raw/sv/app-hosting/for-ai-agenter.md`

## To you, the AI agent

1. Read the whole page before you change anything.
2. Compare the repository with the [checklist](#checklist-for-the-repository).
3. Fix what can be fixed in the repository.
4. Report the rest to the person: what is missing, why, and what the person needs to do in the portal.

Rules that always apply:

- **Never invent features.** If something is not on this page, it does not exist. Do not add platform files, settings or services that the page does not mention, for example a Dockerfile or a deploy configuration of your own, and do not promise the person anything the page does not say. The framework's and tools' ordinary files, such as `tsconfig.json`, are the repository's own.
- **Never put a secret in code, in a committed file or in a public value.** You do not set any values yourself. You tell the person which names are needed and whether each should be **Public** or **Secret**. The values are entered in the portal.
- **If the stack is not supported, stop.** The stack means the language and framework. Do not rebuild the app, and do not wrap it in something that looks supported. See [If the stack is not supported](#if-the-stack-is-not-supported). When the page gives a fix in the repository for a problem, for example an error code with a fix, it is not a stack without support.

## How the platform builds and runs

1. **Analysis.** The portal reads the repository at a specific commit: `package.json`, the lockfile, the framework's configuration files and `.env.example`, and for a Python app `pyproject.toml`, `requirements.txt` and any `Procfile`. The analysis runs no code. It determines the framework, where the app is in the repository, the language version and the package manager.
2. **Install.** The platform installs the dependencies from the committed lockfile, with `devDependencies`, so the build has its tools. A Python app is installed from its dependency file. This is the only step of the build that has network access.
3. **Build.** The platform runs the repository's `build` script (`generate` for a static Nuxt site) without network access. See [Network](#network) for the one exception. A Python app has no build step, except Django's `collectstatic`, which the platform runs.
4. **Image.** The platform packages the result in an image of its own, at most 1 GiB. A Dockerfile in the repository is never used.
5. **Health check.** Before a new version receives traffic, the platform requests `GET /` and waits for a 2xx response.
6. **Running.** The app runs as a container with limited rights. See [The runtime](#the-runtime).

The platform owns the install, the start command, the port and the image. The repository owns the code, the `build` script or the Python app's dependency file, the lockfile and which Node or Python version is used.

A static site is served by the platform's own static server. No server code from the repository runs in production.

### The runtime

- **Start:** chosen by the platform. For a Node app it is always a Node process, for example `node .output/server/index.mjs`, `next start` or `react-router-serve`, and for a Python app `python -m <server>`. The repository's `start` script is only used to see which file starts an Express server, and a `Procfile` only to see which server and which app are started. What a Node server needs at run time must be under `dependencies`.
- **Port:** the app must listen on the `PORT` environment variable (3000) and on `HOST` (`0.0.0.0`). For a Python app, the platform sets the port and address on the server itself.
- **File system:** read-only. Only `/tmp` is writable, and it lives in memory. Nothing there survives a restart or the publication of a new version.
- **Rights:** the app runs as the user `node`, without Linux capabilities and without a way to gain higher privileges.
- **Logs:** write to stdout and stderr.
- **Stop:** the app receives SIGTERM and must exit within 30 seconds. A server of your own, for example Express, must catch SIGTERM itself, close the server and exit.
- **Health check:** `GET /` must answer with a status between 200 and 299 within 3 seconds. The platform does not follow a redirect, so a response such as 301, 302 or 307 counts as a failure. The response must come without signing in. If the check does not pass, the new version never takes over traffic.
- **Health path:** if `/` requires sign-in or redirects, the person can set a path of their own on the app's page, under **Advanced** → **Health path**, for example `/api/health`, `/health`, `/healthz`, `/readyz` or `/up`. The path must answer 200 also to someone who is not signed in. The change applies from the next build.

### Sizes

| Size | CPU | Memory |
| --- | --- | --- |
| Micro | 0.5 vCPU | 1 GB |
| Small | 1 vCPU | 2 GB |
| Medium | 2 vCPU | 4 GB |
| Large | 4 vCPU | 8 GB |

The portal suggests a size, and the person can change it on the app's page.

## What can be built today

### Static sites

| Framework | Recognised by | Built with | Result |
| --- | --- | --- | --- |
| Vite (React, Vue, Svelte without a server) | `vite` | `build` | `dist`, unknown paths get `index.html` |
| Astro, static | `astro`, without `output: 'server'`, `'hybrid'` or an adapter | `build` | `dist` |
| Nuxt, static | `nuxt` with `ssr: false`, the `static` preset, or only a `generate` script | `generate` | `.output/public` |
| Create React App | `react-scripts` | `build` | `build`, unknown paths get `index.html` |
| Angular without SSR | `@angular/core` and `angular.json` | `build` | the build target's `outputPath`, unknown paths get `index.html` |
| Docusaurus | `@docusaurus/core` | `build` | `build` |
| Eleventy | `@11ty/eleventy` | `build` | `_site`, or `dir.output` when it is given as a plain string |
| VitePress | `vitepress` | the script that runs `vitepress build` | `<directory>/.vitepress/dist` |
| Next, export | `next` with `output: 'export'` | `build` | `out` |

Where nothing else is stated, an unknown path gets the site's own 404 page.

### Node servers

| Framework | Condition | Started with |
| --- | --- | --- |
| Nuxt | no `nitro.preset` of its own in `nuxt.config` | Nitro's server in `.output` |
| TanStack Start (for example from Lovable) | at the repository root: `build` is exactly `vite build`, and the configuration is named `vite.config.ts` | Nitro's server in `.output` |
| Analog | `@analogjs/platform` | Nitro's server in `dist/analog` |
| Nitro | `nitro` or `nitropack` | Nitro's server in `.output` |
| Next | `output: 'standalone'`, or `next start` with `next` under `dependencies` | `server.js` or `next start` |
| React Router (framework mode) | `@react-router/serve` under `dependencies` | `react-router-serve` |
| SvelteKit | `@sveltejs/adapter-node`, and no other adapter | `node build/index.js` |
| Express | `express` under `dependencies`, a `build` script, and a `start:prod` or `start` script that is exactly `node <directory>/<file>.js`, where the directory is written by the build and is not in the repository | `node <directory>/<file>.js` |

The platform sets Nitro's preset to `node-server`. In Nuxt, Analog and TanStack Start, a preset set in the app's configuration, for example for Vercel, Netlify or Cloudflare, wins over the platform's, and the build is then stopped. Remove it.

### Python apps

| Framework | Started with | Condition |
| --- | --- | --- |
| Django | uvicorn with `ASGI_APPLICATION`, or gunicorn with `WSGI_APPLICATION` | `manage.py` and the settings name the modules as plain text |
| FastAPI, Starlette, Litestar | uvicorn, `module:app` | the app is created at module level, for example `app = FastAPI()`, and `uvicorn` (or `fastapi[standard]`) is a dependency |
| Flask | gunicorn, `module:app` or `module:create_app()` | `app = Flask(...)`, or only a factory `def create_app(`, and `gunicorn` is a dependency |
| Streamlit | `streamlit run <file>` | exactly one file imports streamlit |
| Gradio | the platform's launcher runs the file | exactly one file imports gradio and launches the app |

The platform looks for the file that creates the app itself. If it finds none, or several, or the project has more than one web framework, name the app in a `Procfile`, for example `web: uvicorn main:app`. The line must start with `gunicorn`, `uvicorn`, `streamlit run` or, for Gradio, `python <file>`. The platform sets the port, address and number of workers itself, so flags on the line are not used. Only `web:` runs: a `release:` line, for example migrations, and other processes do not.

**Dependencies.** The repository has exactly one of these:

- `pyproject.toml` with `uv.lock` (uv).
- `pyproject.toml` with `poetry.lock` (Poetry). The platform only installs the dependencies, so a Poetry project that is a package needs `package-mode = false`.
- `requirements.txt`. It is installed as it is only if every line is pinned with a hash. Otherwise the platform resolves it once, and the result belongs to the version.

The server that starts the app (uvicorn, gunicorn, streamlit or gradio) must be among the dependencies. The platform never adds a package.

**Python version.** 3.12, 3.13, 3.14 or 3.15, from `.python-version` or `requires-python`. If the repository states no version, the app is built with 3.14. `runtime.txt` is not read.

**Django:**

- The platform reads the project's settings and only adds the health check's own name to `ALLOWED_HOSTS`. You put the app's addresses, the platform address and custom domains, in `ALLOWED_HOSTS` yourself.
- The platform runs `collectstatic` during the build, without network, when `django.contrib.staticfiles` is installed and `STATIC_ROOT` is inside the app. During the build, `SECRET_KEY` and `DJANGO_SECRET_KEY` have a temporary value, and no other secret values exist. The settings must be importable without them, or the build fails.
- The app server serves no static files. Add `whitenoise` and its middleware, or pages load without their CSS and JavaScript.
- The platform runs no migrations.

### Apps in a subdirectory

An app does not have to be at the repository root. Vite, Create React App, Angular, VitePress, Docusaurus, Eleventy, Next, Nuxt as a server, Analog, Nitro, React Router, SvelteKit and Express are also built in a subdirectory. TanStack Start is built in a subdirectory when it has `nitro` or `nitropack` as a dependency of its own. Astro and static Nuxt are only built at the repository root.

In a workspace (npm, pnpm or yarn workspaces) two limits apply:

- Packages in the same repository that must be built before the app are not supported yet.
- A server app whose dependencies are installed at the workspace root is not supported yet. A Next app is built with `output: 'standalone'` in `next.config`.

### What is not built

- **Backends in languages other than JavaScript and Python:** Go, .NET, PHP, Ruby and Java. Such a repository gives `BUILD_PROFILE_UNSUPPORTED`, or `BUILD_SOURCE_HAS_DOCKERFILE` if it has a Dockerfile.
- **Python apps with other web frameworks** than those in the table, or that need Pipenv, PDM, Conda or only `setup.py`.
- **Python apps that need system packages** (`Aptfile`, `packages.txt`) **or a browser** (for example Playwright or Selenium).
- **Background jobs and schedulers.** Only the web process runs.
- **A Dockerfile of its own without a framework the platform recognises** (`BUILD_SOURCE_HAS_DOCKERFILE`). When the platform recognises the framework, the Dockerfile is not used, and the analysis says so (`SOURCE_DOCKERFILE_NOT_USED`).
- **Remix, Vike, SolidStart, Qwik City and Astro with a server** (`output: 'server'`, `'hybrid'` or an adapter).
- **Angular with SSR**, and **React Router with `ssr: false`**.
- **An Express server that runs its source directly**, for example with `ts-node`, `tsx` or `node src/index.js` where `src` is in the repository. It is built when `build` writes the server to a directory and `start` runs the built file, see `BUILD_SERVER_START_UNSUPPORTED`.
- **Repositories that only have a bun lockfile** (`bun.lock` or `bun.lockb`).
- **Private repositories connected with an access token.** A private repository is built when it is connected with CoreIT's GitHub App.

## Checklist for the repository

Go through the items in order and fix what does not hold. Most items stop the build or the running app if they do not hold. The items under **Values** protect the secrets.

**Framework and location**

- [ ] The app uses a framework from the tables above, in a way the table describes.
- [ ] The repository has no Dockerfile as the only way to build the app.

**Node: `package.json` and lockfile**

- [ ] `package.json` has a `build` script. A static Nuxt site has a `generate` script.
- [ ] The repository has exactly one lockfile, and it is committed: `package-lock.json`, `pnpm-lock.yaml` or `yarn.lock`.
- [ ] The lockfile matches `package.json`. Run the install locally with a frozen lockfile (`npm ci`, `pnpm install --frozen-lockfile` or `yarn install --immutable`) and check that it succeeds.
- [ ] If `package.json` has a `packageManager` field, it names the same tool as the lockfile and an exact version, for example `pnpm@9.15.9`, not a range.
- [ ] If the repository uses yarn 2 or later, `.yarnrc.yml` has the line `nodeLinker: node-modules`.
- [ ] What starts the server is under `dependencies`, not `devDependencies`: for example `next`, `@react-router/serve` or `express`.

**Node version**

- [ ] If the repository states a Node version, it is 22, 24 or 26. State it in `.nvmrc`, `.node-version` or `engines.node`. If the repository states none, the app is built with Node 22.
- [ ] If the repository states the Node version in several places, they agree.

**Python**

- [ ] The repository has exactly one dependency file: `uv.lock` or `poetry.lock` together with `pyproject.toml`, or `requirements.txt`.
- [ ] The server that starts the app (uvicorn, gunicorn, streamlit or gradio) is among the dependencies.
- [ ] If the repository states a Python version, it is 3.12, 3.13, 3.14 or 3.15, in `.python-version` or `requires-python`, and they agree.
- [ ] If the platform cannot find the app by itself, a `Procfile` with a `web:` line names it.
- [ ] Django: `ALLOWED_HOSTS` has the app's addresses, `whitenoise` serves the static files, and the settings can be imported without secrets other than `SECRET_KEY`.

**The build**

- [ ] The build succeeds without network access after the install. It fetches no data, files or fonts from the internet during `build`. The exception is Next's `next/font/google`.
- [ ] The build writes its result where the table says.
- [ ] For Express: the directory that `start` points to is written by the build and is not committed.

**The runtime**

- [ ] The server listens on `PORT` and `HOST` from the environment, not on a hard-coded port.
- [ ] `GET /` answers 200–299 within 3 seconds, without sign-in and without a redirect. Otherwise there is a health path that does.
- [ ] The app only writes to `/tmp`, and it copes with everything there disappearing.
- [ ] The app exits on SIGTERM within 30 seconds.
- [ ] The server calls no services on the internet. See [Network](#network).

**Values**

- [ ] No secret is in the code or in a committed file. No `.env` file is committed.
- [ ] No name with a public prefix contains `SECRET`, `PRIVATE`, `SERVICE_ROLE`, `PASSWORD`, `PASSWD` or `CREDENTIAL`.
- [ ] `.env.example` lists every name the app reads, with an empty value.

## Public and Secret

Every value the app reads has one of two placements in the portal:

- **Public** — "visible to anyone who visits the app". The value is built into the app when it is built. If it changes, a new build is needed.
- **Secret** — "only the app's server reads it". The value reaches the app when a version is published, and it is never built in.

The portal suggests the placement from the name, and a person confirms it. A public value goes into the build only once someone has confirmed it as public.

A static site has no server, so it has no secret values. Everything a static site needs is public and visible in the browser.

### Public prefixes

Names that start with `VITE_`, `NEXT_PUBLIC_`, `NUXT_PUBLIC_`, `PUBLIC_` or `REACT_APP_` are read by the framework when the app is built, and the value ends up in the code the browser downloads. There is no way to make such a value secret.

The build is stopped with `BUILD_INPUT_SECRECY` if a name with the prefix `VITE_`, `NEXT_PUBLIC_`, `PUBLIC_` or `REACT_APP_` contains `SECRET`, `PRIVATE`, `SERVICE_ROLE`, `PASSWORD`, `PASSWD` or `CREDENTIAL`. The check does not cover `NUXT_PUBLIC_`, but such a value is just as public.

### Rules for names and values

- A name consists of letters, digits and underscores, does not start with a digit and is at most 128 characters.
- The platform sets these names itself, and they cannot be used: `PORT`, `HOST`, `HOSTNAME`, `NODE_ENV`, `PATH` and `NODE_OPTIONS`, and for Python `PYTHONPATH`, `PYTHONHOME`, `VIRTUAL_ENV`, `DJANGO_SETTINGS_MODULE`, `COREIT_DJANGO_SETTINGS_MODULE`, `GRADIO_SERVER_NAME`, `GRADIO_SERVER_PORT`, `STREAMLIT_SERVER_PORT` and `STREAMLIT_SERVER_ADDRESS`.
- A value cannot contain line breaks. A value on several lines, for example a PEM key, needs to be encoded, for example with base64, and decoded by the app.

### `.env.example`

The portal reads `.env.example` (or `.env.sample` or `.env.template`) to know which values the app needs:

- `NAME=` with an empty value means the value is required.
- `NAME=` with a comment that says it is optional, for example `# optional` or `# valfri`, means the value may be empty. The comment is on the line above, or after the value on the same line.
- `NAME=something` with a value means nothing needs to be given. So do not write example values for anything that really must be given.
- The names the platform sets itself, for example `PORT` and `HOST`, are not listed.

A committed `.env`, `.env.local`, `.env.production` or `.env.development` gives the warning `COMMITTED_ENV_FILE`. Remove the file from the repository and ask the person to replace the values that were in it.

## Network

**During the build** only the install has network access. The build itself runs without network, with one exception: Next's `next/font/google` may fetch fonts from Google Fonts. Any other network call during the build makes the build fail with `BUILD_CODE_FAILED`. That includes, for example, fetching content from a CMS or an API when pages are prerendered.

**In production** the app's server does not reach the internet. Calls made by the browser are not affected.

This means the app's server cannot call, for example, Supabase, Stripe, an AI API or an external database today. What can be done from the browser works. A server that renders pages must not wait for an external service, because the answer never comes and the health check then fails.

If the app's server needs to reach a service on the internet: fill in the [runtime inventory](#if-the-stack-is-not-supported) and ask the person to send it to CoreIT.

## Supabase

The import does not move the Supabase project. It stays where it is, and the app keeps using it.

- **From the browser:** the project's URL and the anon or publishable key are public values, for example `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Data is protected by Supabase's row-level security (RLS), because the key is visible to everyone.
- **The service_role key:** gives full access to the database and must never be in the app. A name with a public prefix and `SERVICE_ROLE` stops the analysis (`SUPABASE_SERVICE_ROLE_FRONTEND`) and the build (`BUILD_INPUT_SECRECY`). It belongs in Supabase Edge Functions, where it is set as a secret at Supabase. If the key has already been behind a public prefix in a published app, ask the person to replace it in Supabase.
- **Edge Functions:** keep running at Supabase. The platform does not build them.
- **The address in the code:** if the Supabase address is written directly in the source code, you get a notice (`SUPABASE_CLIENT_CONFIG_INLINED`). Prefer reading it from a public value.

### Apps from Lovable

- **Lovable Cloud's sign-in** (`@lovable.dev/cloud-auth-js`, which sends the browser to `/~oauth/initiate`) does not work outside Lovable. Before such a version is published, someone with the right to publish must choose **Publish anyway**. The fix is to give the app a sign-in of its own, for example Supabase's Google sign-in with an OAuth client of its own where the app's own domains are allowed return addresses.
- **Images from Lovable's storage** (paths that start with `/__l5e/assets-v1/`) are not shown outside Lovable, and the analysis warns about them. Move the images to `public/` and use ordinary paths.

## Error codes and what to do

The codes below are the ones that can be fixed in the repository. Other errors are the platform's, and the portal then says that the error is not in the code.

| Code | Means | Do this |
| --- | --- | --- |
| `BUILD_PROFILE_UNSUPPORTED` | The framework or language is not built. | See [If the stack is not supported](#if-the-stack-is-not-supported). |
| `BUILD_SOURCE_HAS_DOCKERFILE` | The repository has a Dockerfile and no framework the platform recognises. | If the app is built with a framework from the tables, make sure it shows in `package.json`. Otherwise: see [If the stack is not supported](#if-the-stack-is-not-supported). |
| `BUILD_PACKAGE_MANAGER_UNSUPPORTED` | The repository uses bun. | Switch to npm, pnpm or yarn, commit that lockfile and remove `bun.lock` or `bun.lockb`. |
| `BUILD_SCRIPT_MISSING` | `package.json` lacks the script that builds the app. | Add `build` (`generate` for a static Nuxt site). |
| `BUILD_PROJECT_ROOT_UNSUPPORTED` | The app is in a subdirectory, and the framework is not built there. | See [Apps in a subdirectory](#apps-in-a-subdirectory). |
| `BUILD_PROJECT_ROOT_MISSING` | The app's directory is not in the repository at this commit. | Ask the person to choose the app again under **Code** on the app's page. |
| `BUILD_WORKSPACE_DEPENDENCY_BUILD_UNSUPPORTED` | The app uses packages in the same repository that must be built first. | Not supported yet. Report it to the person. |
| `BUILD_WORKSPACE_PROD_DEPS_UNSUPPORTED` | A server app in a workspace, whose dependencies are installed at the workspace root. | For Next: set `output: 'standalone'` in `next.config`. Otherwise it is not supported yet. |
| `BUILD_NODE_VERSION_UNSUPPORTED` | The repository asks for a Node version that is not built. | State 22, 24 or 26. The platform never upgrades silently. |
| `BUILD_NODE_VERSION_CONTRADICTORY` | `.nvmrc`, `.node-version` and `engines.node` say different things. | Make them state the same major, or keep only one. |
| `BUILD_NODE_VERSION_UNREADABLE` | The Node version could not be read. | Write a number, for example `22`, in `.nvmrc` or `.node-version`, and an ordinary range in `engines.node`. |
| `BUILD_STATIC_OUTPUT_UNREADABLE` | Where the build puts its files could not be read. | State the directory as a plain string in the configuration, for example `outputPath` in `angular.json` or `dir.output` in Eleventy, not as a variable or an expression. |
| `BUILD_SERVER_ADAPTER_UNSUPPORTED` | SvelteKit builds with an adapter for another service, or with several. | Use `@sveltejs/adapter-node`. |
| `BUILD_SERVER_START_UNSUPPORTED` | How the server starts could not be determined. | React Router: put `@react-router/serve` under `dependencies`. Express: make `build` write the server to a directory that is not committed, and make `start` exactly `node <directory>/<file>.js`. |
| `RECIPE_YARN_PNP_UNSUPPORTED` | Yarn's Plug'n'Play leaves no `node_modules`. | Set `nodeLinker: node-modules` in `.yarnrc.yml`. |
| `RECIPE_START_MISSING` | What starts the server was not included in the package. | Move the framework's server (for example `next` or `@react-router/serve`) from `devDependencies` to `dependencies`. |
| `BUILD_DEPENDENCIES_FAILED` | The install failed. | Check that the lockfile is committed and matches `package.json`, and that `packageManager` states an exact version. The error output in the portal says where the install stopped. |
| `BUILD_CODE_FAILED` | `build` failed. | Build locally after an install from the lockfile and fix the error. Check that the build makes no network calls. |
| `BUILD_ARTIFACT_TOO_LARGE` | The image grew larger than 1 GiB. | Reduce the app's size, for example large files in `public/` or unnecessary packages under `dependencies`. |
| `BUILD_INPUT_SECRECY` | A public name looks like a secret. | If the value is secret: rename it without a public prefix and read it on the server. A static site has no server, so there the value must not be in the app at all. If it is public: rename it so it does not contain the words above. |
| `RECIPE_NO_LONGER_VALID` | An accepted AI proposal for the build no longer matches the repository (script, directory, lockfile or output). | Fix the repository so it matches again, or ask the person to analyse again and accept a new proposal. |
| `PYTHON_LOCKFILE_MISSING` | `pyproject.toml` has no lockfile. | Run `uv lock` (or `poetry lock`) and commit the lockfile. |
| `PYTHON_DEPENDENCY_FILES_AMBIGUOUS` | The project has dependency files for more than one package manager. | Remove the ones that are not used. |
| `PYTHON_PIPENV_UNSUPPORTED`, `PYTHON_PDM_UNSUPPORTED`, `PYTHON_SETUP_PY_UNSUPPORTED` | Pipenv, PDM or only `setup.py`. | State the dependencies in `pyproject.toml` with `uv.lock` or `poetry.lock`, or in `requirements.txt`. |
| `PYTHON_CONDA_UNSUPPORTED` | A Conda environment. | Not built. See [If the stack is not supported](#if-the-stack-is-not-supported). |
| `PYTHON_POETRY_PACKAGE_UNSUPPORTED` | The Poetry project is a package that must be installed. | Set `package-mode = false` under `[tool.poetry]`. |
| `PYTHON_PYPROJECT_UNREADABLE` | `pyproject.toml` is not valid TOML. | Fix the file. |
| `BUILD_PYTHON_VERSION_UNSUPPORTED` | The Python version is not built. | State 3.12, 3.13, 3.14 or 3.15. |
| `BUILD_PYTHON_VERSION_CONTRADICTORY` | `.python-version` and `requires-python` disagree. | Make them state the same version. |
| `BUILD_PYTHON_VERSION_UNREADABLE` | The Python version could not be read. | Write, for example, `3.14` in `.python-version`. |
| `BUILD_PYTHON_RUNTIME_TXT_UNSUPPORTED` | `runtime.txt` is not read. | State the version in `.python-version` and remove `runtime.txt`. |
| `PYTHON_FRAMEWORK_UNKNOWN` | No web framework the platform starts is among the dependencies. | See [If the stack is not supported](#if-the-stack-is-not-supported). |
| `PYTHON_FRAMEWORK_AMBIGUOUS`, `PYTHON_ENTRYPOINT_NOT_FOUND`, `PYTHON_ENTRYPOINT_AMBIGUOUS` | More than one framework, or no file or several files that could be the app. | Name the app in a `Procfile`, for example `web: uvicorn main:app`. |
| `PYTHON_SERVER_MISSING` | The server that starts the app is not a dependency. | Add `uvicorn` or `gunicorn` to the dependencies. |
| `PYTHON_PROCFILE_UNSUPPORTED` | The Procfile's `web:` line has a form the platform does not read. | Start the line with `gunicorn`, `uvicorn`, `streamlit run` or, for Gradio, `python <file>`. |
| `PYTHON_DJANGO_SETTINGS_UNREADABLE` | The Django settings cannot be read. | Name the modules as plain text in `manage.py` and the settings. |
| `PYTHON_SYSTEM_PACKAGES_UNSUPPORTED`, `PYTHON_BROWSER_UNSUPPORTED` | The app needs system packages or a browser. | Not supported. See [If the stack is not supported](#if-the-stack-is-not-supported). |
| `PYTHON_DJANGO_STATIC_NOT_SERVED` | A notice: nothing serves Django's static files. | Add `whitenoise` and its middleware. |
| `SUPABASE_SERVICE_ROLE_FRONTEND` | Supabase's service_role key has a public name. | Remove it from the app. See [Supabase](#supabase). |
| `COMMITTED_ENV_FILE` | A `.env` file (`.env`, `.env.local`, `.env.production` or `.env.development`) is committed. | Remove it from the repository, add it to `.gitignore` and ask the person to replace the values. |

## If the stack is not supported

If the app's stack is not supported, for example a backend in Go or a Python app that needs a browser:

1. **Stop.** Say it plainly to the person: App Platform does not build this stack today.
2. **Do not build around it.** Write no Dockerfile and no npm wrapper around another language. The platform never builds a Dockerfile, and a wrapper that starts another process through npm is not run.
3. **Fill in the runtime inventory** below, from what you see in the repository. Do not guess. Write "unknown" where the repository does not answer.
4. **Ask the person to send the inventory** to CoreIT through [Contact support](/en/support/contact-support).

Do not add the block for `AGENTS.md`, since the app does not run on App Platform.

## Put this in the repository

Put the block in `AGENTS.md` or `CLAUDE.md` at the repository root, so that every agent working in the repository follows the rules.

```markdown
## Running on CoreIT App Platform

The app runs on CoreIT App Platform. Read the contract before you change the build,
dependencies, start or environment variables:
https://docs.coreit.cloud/raw/en/app-hosting/for-ai-agents.md

Hard rules:
1. No Dockerfile for running the app. The platform never builds a Dockerfile.
2. Node: a build script in package.json (generate for static Nuxt) and exactly one
   committed lockfile: npm, pnpm or yarn, never only bun.
3. Python: exactly one dependency file (uv.lock or poetry.lock with pyproject.toml, or
   requirements.txt), and the server (uvicorn, gunicorn, streamlit, gradio) among the dependencies.
4. Node 22, 24 or 26 and Python 3.12–3.15, the same version everywhere it is stated.
5. A Node server listens on PORT and HOST, and the start package is under dependencies.
6. GET / (or the health path) answers 2xx within 3 s, without sign-in and without a redirect.
7. Write only to /tmp, log to stdout and exit on SIGTERM within 30 s.
8. No network calls during the build, and no calls from the server to the internet.
9. No secrets in code, in committed files or behind a public prefix.
10. If the stack is not supported: stop and say so. Never invent features.
```
