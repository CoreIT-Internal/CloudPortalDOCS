# Import app

With the import wizard you bring home an app you built in Lovable, Cursor, Claude Code, Bolt or any Git repository. Your code stays where it is. The portal reads the repository, chooses most things for you and prepares hosting.

::note
The import does not change your repository or your build tool. It does not move your database either.
::

## Before you start

- Make sure your latest code is pushed to the repository.
- If you build in Lovable: connect the project to GitHub and check that the latest version is synced.
- To pick the repository from a list, a GitHub account must be connected. See [Connect GitHub](/en/app-hosting/connect-github).

## Start the import

Select **Import** in the menu, or one of the cards **Bring your Lovable app home** and **Bring an app home from Git** on the start page. All of them open the same wizard.

The wizard has three steps: **1. Connect the repository**, **2. What we found** and **3. Finish**. **Next** takes you forward and **Back** one step back.

::note
The app is created when you select **Next** in step 1. If you leave the wizard after that, the app remains under **My apps**.
::

## Step 1 – Connect the repository

At the top, "Connect your Git repository" shows a short checklist. If you built the app in Lovable, open "Did you build the app in Lovable? Export it to GitHub first" for the steps in Lovable.

1. Enter an **Application name**.
2. Under "Which environments do you want to create?", choose:
   - **Test + Production** (marked **Recommended**) — a test environment lets you keep building without testing directly in production.
   - **Production only** — just one production environment.
3. Choose how the portal reaches the repository (see below).
4. Select **Next**. The portal now reads your repository.

Read more about environments in [Secrets and environments](/en/app-hosting/secrets-and-environments).

### Choose how the portal reaches the repository

Which options you see depends on your permissions.

**GitHub (recommended)** — "Pick the repo from a list — the app only sees repos you granted it access to." Requires **Manage providers and source connections**.

- If no GitHub account is connected, **Connect GitHub →** is shown. See [Connect GitHub](/en/app-hosting/connect-github).
- If your organization has several connected accounts, choose the account under **GitHub account**.
- Choose the repository under **Choose repo**. If you have many repositories, you can search the list.
- If a repository is missing, select **＋ Select more repos in GitHub ↗** and give the app access there. Then select **⟳ Refresh**.
- **＋ Connect more GitHub accounts ↗** installs the app on another account. CoreIT links a new account, see [Connect GitHub](/en/app-hosting/connect-github).
- Choose the **Branch** from the list. The repository's default branch is preselected.

**Use a connection that already exists** — shown when an administrator has already connected access to your repositories: "…you do not need to handle a token yourself."

1. Choose the connection under **Choose a connection…**.
2. Enter the **Git repository URL**, for example `https://github.com/yourcompany/myapp`.
3. Enter the **Branch**.

**Use a PAT or public repo instead (advanced)** — for repositories you enter by URL, for example on GitLab or Azure DevOps.

1. Enter the **Git repository URL** and the **Branch**.
2. Under **Repository access**, choose **Public repository** or **Private — personal access token (PAT)**.
3. For a private repository, paste a token with read access to the repository. It is stored encrypted.

The token option requires **Manage providers and source connections**. Without that permission you can only import public repositories. If there is also no connection to choose, the box "A private repository has to be connected by an administrator" is shown.

::tip
A connection created here, with GitHub or a token, is saved. Others in the organization can then choose it under **Use a connection that already exists** without handling a token themselves.
::

## Step 2 – What we found

"We read your repository and chose the rest. Change anything that looks wrong — otherwise there is nothing to do here." While the portal reads the repository, it says "Reading your repository …".

### Build configuration

The card shows what the portal found: **Framework**, **Runtime**, **Build command** and **Package manager**. Select **Change** if something is wrong, correct the values and select **Done**.

::tip
If the package manager is uncertain, look for a lockfile in the repository: `package-lock.json` = npm, `pnpm-lock.yaml` = pnpm, `yarn.lock` = yarn, `bun.lockb` = bun.
::

The same card also shows:

- **Size** — for example "0.5 CPU · 1 GB RAM · 10 GB storage" and "Chosen automatically". CPU can be a fraction of a core. If the size is not decided yet, it says "Size is chosen when the hosting location is prepared". You can change the size later on the app's page.
- **Hosting location** — where the app will run, for example **CoreIT Hosting**. CoreIT chooses the hosting location.

If there is no hosting location yet, "We are preparing a hosting location for your app" is shown. You do not need to do anything. The import can still be completed.

### Environment variables

If the app needs values that are missing, the box "Your app needs these values" is shown, with one line per value, for example "Your app needs `VITE_SUPABASE_URL` before it can be put into service."

The **Environment variables** list shows the variables the portal found in the code. Add a value like this:

1. Enter the **Key** and the **Value**.
2. Select **Add secret**.

The values are recommended but not required to continue. You need the **Manage environment variables and secrets** permission.

::warning
This is the only place where you add environment variables yourself. The app's page has no editor for them. Read [Secrets and environments](/en/app-hosting/secrets-and-environments) before you add secret keys.
::

When you are done, select **Prepare hosting**.

## Step 3 – Finish

The portal confirms: "Your app is analyzed and prepared. Next, CoreIT activates hosting — nothing is needed from you."

Below the confirmation it says "The app is not running yet. This prepares the hosting environment and the deployment plan — CoreIT puts the app into service for you."

Select **My apps** to return to the start page.

## After the import

The app is listed under **My apps**. On the app's page you follow its status and address, see [Your app](/en/app-hosting/deploy-app).

Keep developing in your tool as usual. When the repository has changed since the last analysis, the app's page shows "A new version is available in GitHub". Select **Analyze again** to read in the latest code. This requires the **Analyze repositories** permission.
