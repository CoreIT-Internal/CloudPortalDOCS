# Secrets and environments

Environment variables and secrets control how your app connects to databases and external services. You add them in the import wizard's **What we found** step. See [Import app](/en/app-hosting/import-app).

::warning
You only add values during the import, and they apply to the production environment. The app's page has no editor for environment variables. If you need to add or change a value after the import, [contact support](/en/support/contact-support) and CoreIT will help you.
::

## Who can add values

You need the **Manage environment variables and secrets** permission. It is a sensitive permission that Owner, Admin and Operator have by default. Member does not have it.

Without the permission, the portal answers "You do not have permission for this action." when you try to add a value.

## Public values and server values

The portal decides the type from the value's name. You do not choose it yourself.

- **Public** — names that start with `VITE_`, `NEXT_PUBLIC_`, `NUXT_PUBLIC_`, `PUBLIC_` or `REACT_APP_`. They are built into the app when it is built and are visible in the browser.
- **Server** — all other names. They are only used on the server.

::warning
Public values are visible to everyone who opens the app. Never give a secret key a name with a public prefix.
::

## Add a value

In step 2 of the import, **What we found**:

1. Go through the **Environment variables** list. It shows the variables the portal found in the code.
2. Enter the **Key** and the **Value**.
3. Select **Add secret**.

The list updates right away. The values are recommended but not required to continue.

In the list, the markers mean:

- ⚠️ — the value is missing. ✅ — the value is set.
- **Build variable · Public after build** — a public value that is built into the app.
- **Server / runtime** — a server value.
- **Found in the code** — the app's code reads the value, but the repository does not say it is required. Fill it in if the app needs it.

If values the app needs are missing, the box "Your app needs these values" is shown, with one line per value, for example "Your app needs `VITE_SUPABASE_URL` before it can be put into service."

## Common variables

The portal gives guidance for common values. Some examples:

- **Supabase URL** — your Supabase project's API URL (Project Settings → API → Project URL).
- **Supabase anon/publishable key** — the public key, normally harmless in the frontend (Project Settings → API → anon/public).
- **Supabase service_role key** — full admin access. Server only, never in the frontend.
- **Database connection string** — server only.
- **Stripe** — use the publishable key in the frontend and the secret key only on the server.

::warning
The Supabase service_role key grants full access to your database. Never give it a name with a public prefix, for example `VITE_`.
::

## After the import

On the app's page, the **Environment variables** row shows how many values are set, for example "3 configured", and how many are missing. Missing values are also listed in the "Your app needs these values" box. See [Your app](/en/app-hosting/deploy-app).

## Environments (test and production)

In the first step of the import you choose environments:

- **Test + Production** — the app gets two environments, `production` and `staging`.
- **Production only** — the app only gets `production`.

On the app's page you switch environment with the **Environment** selector.

The wizard only prepares the production environment. The environment variables you add, the hosting location and the size apply to production. The test environment is created, but gets neither a hosting location nor environment variables in the wizard.

::note
Environment variables belong to one environment. Values you add for production do not apply to the test environment. If you want to change the environments after the import, for example add a test environment, [contact support](/en/support/contact-support).
::
