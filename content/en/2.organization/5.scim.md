# SCIM provisioning

SCIM lets your identity provider (e.g. Microsoft Entra ID) **create and update users automatically** in CloudPortal and **assign roles via groups**. SSO handles sign-in — SCIM handles which accounts exist and what they may do.

::note
SCIM requires [SSO](/en/organization/sso) to be set up first. The **SCIM Provisioning** section is shown under **Settings** → **Access** → **Auth & SSO** when the organization has a connection to an identity provider. Providers and distributors configure SCIM for their own tenant, see [Sign-in and SCIM for partners](/en/partner/sign-in-and-scim).
::

## Enabling SCIM

1. Go to **Settings** → **Access** → **Auth & SSO** → **SCIM Provisioning**.
2. Click **Generate new token**. The portal shows a **bearer token only once** — copy it right away (it cannot be shown again).
3. Note the **Tenant URL** the portal shows:
   ```
   https://<your-domain>/api/scim/v2
   ```

## Connecting your identity provider

In, for example, Entra (Enterprise Application → Provisioning):

1. Set **Provisioning Mode** to *Automatic*.
2. Under **Admin Credentials**:
   - **Tenant URL** → paste `https://<your-domain>/api/scim/v2`
   - **Secret Token** → paste the token from the portal
3. Click **Test Connection** to verify.
4. Enable group provisioning and assign the users/groups to sync.
5. Start provisioning.

::note
The first sync can take a while. After it, a sync runs approximately every 40 minutes. Synced groups appear in the portal but grant **no access** until you have linked them to roles (below).
::

## Linking groups to roles

In the **Group–role mappings** section you link a synced group to permissions:

1. Click **Add mapping** and choose a **Group**.
2. Choose a **Type**:
   - **Organization role** — Admin, Operator, Member, Viewer or Support
   - **Module bundle** — a combined level for a module
   - **Provisioning** — presence only, no permission
   - **Single permission (advanced)** — a single permission in a module
3. Choose what should happen **When removed from group**. The options depend on the type:
   - **Remove permission** — available for all types and recommended.
   - **Downgrade to default role** — only for Organization role.
   - **No action (provisioning only)** — only for Provisioning.
4. Click **Add**. Users in the group get the role **immediately** — no new sync is needed.

With **Remove all** you remove a group's mappings. SCIM then no longer assigns what they gave to the group's members.

The synced groups are also shown under [Groups](/en/organization/groups) with the source **From SCIM**. There you can give them module permissions, but name and members are changed in the identity provider.

### Groups that need attention

A group's identity is its id in the directory, never its name. If a group lacks that link, or the directory has changed the group's id, it is shown in the **Groups that need attention** box:

- **Not bound** — the group was created before groups were linked to their id in the directory.
- **Identity changed** — the directory has changed the group's id.

In both cases it says "Mappings do not apply" until you have dealt with the group:

- **Bind** — enter **The group's id in the directory**, exactly as the directory sends it, and select **Bind group**. Check the id in the directory before you bind.
- **Delete** — the group and its mappings are deleted, and what they gave is revoked for all members. If the group still exists in the directory, it is created again, without mappings.

## At provider and distributor level

A provider or distributor that uses SCIM for its own tenant maps groups differently. There are only two types there, and organization roles cannot be chosen:

- **MSP role** — the group's members get an MSP role. Under **Applies to** you choose **The distributor's entire customer tree** (distributors only), **One provider's customers**, **Selected customers** or **Provider administration only**. With selected customers the role applies only at those customers, and only as long as the tenant reaches them.
- **Tenant role: Admin** — the group's members become administrators of the tenant. The type requires the tenant to have a recovery administrator, and is otherwise shown as "Tenant role: Admin (needs a recovery administrator)".

If SCIM is turned off at tenant level, what SCIM gave remains. The "SCIM is off, but what SCIM gave is still there" box then has the **Revoke what SCIM gave** button.

Read more under [Sign-in and SCIM for partners](/en/partner/sign-in-and-scim) and [Roles and permissions for partners](/en/partner/roles-and-permissions).

## Managing tokens

The **Tokens** list shows, for each token, its beginning, when it was created, when it was last used and whether it is revoked.

- **Revoke** — the token stops working, and Entra ID can no longer provision users with it. This cannot be undone.
- **Disable SCIM** — all SCIM tokens are revoked and provisioning from Entra ID stops.
