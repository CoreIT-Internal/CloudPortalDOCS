# Autonomous agents

An autonomous agent works on its own, without any person signed in. It signs in as itself with its own identity in Microsoft Entra ID. In Microsoft Foundry this is called an **agent identity**. An agent gets nothing automatically: an administrator gives it its own, explicit mandate in the organization.

::note
To register or revoke agents you need the **Organization administration** permission, and the [AI policy](/en/ai-clients/ai-policy) must allow AI clients.
::

## How it fits together

- **The agent** is the identity in Microsoft Entra ID, with a tenant id, an object id and an app id.
- **The Mcp.Agent role** in Entra gives the agent the right to call CloudPortal at all.
- **The mandate in the portal** says what the agent may do, in which organization and for how long. Without a mandate the agent is refused, even with the role.
- The agent's calls are capped by **your** permissions. If you lose your administrator role, the mandate rests until the role is restored.
- If the organization's [AI policy](/en/ai-clients/ai-policy) requires that whoever gave the connection its permission does not approve, you cannot approve proposals created by an agent you gave a mandate. Another person must then do it. An agent has no verified person behind it, so a sensitive change from it is approved by the customer's provider.

## 1. Prepare the agent in Microsoft Foundry

1. Go to **Tools** in your Foundry project and choose **Connect a tool** → **Custom** → **Model Context Protocol (MCP)**.
2. Enter a name and the **MCP address**. Under **Authentication** choose **Microsoft Entra** with the type **Agent identity**.
3. As the **Audience**, enter the value you have received from CoreIT for the CloudPortal API.
4. Add the tool to the agent.

::tip
Should two agents reach two different customers? Create two agents. Each has its own identity and gets its own mandate.
::

## 2. Give the agent the Mcp.Agent role

An administrator in your Microsoft Entra tenant assigns the agent identity the **Mcp.Agent** application role for the CloudPortal API.

::warning
Do this **before** the agent is used for the first time. Foundry reuses its sign-in for up to about an hour, so a role assigned afterwards shows only when the sign-in is renewed.
::

## 3. Register the agent in the portal

1. Switch to the organization the agent should reach.
2. Open **Settings** → **Services** → **AI** and click **Register agent**.
3. Give the agent a name and enter its **Tenant id**, **Object id (service principal)** and **App id (client id)** from Microsoft Entra ID.
4. Choose what the agent may do and how long the mandate lasts, at most 90 days.
5. Click **Register agent**.

The agent then shows under **Connections to the organization**.

## Revoke an agent

Click **Revoke here** on the agent. The agent is refused from the next call. The mandate also stops applying when it expires, when you lose your administrator role and when the AI policy is turned off.
